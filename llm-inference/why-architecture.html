LLM Inference Field Guide · Part 4

Why each part is built this way, and what happens if you change it

Every architecture choice in Qwen, Gemma and DeepSeek exists to fix a measurable problem, and each fix has a price. Every section here is laid out the same way, so you can reason like a designer: if I change this, what goes up, what goes down, and why.

The four meters every design trades against

used in every section
① Memory heldWeights + KV cache × number of chats. Decides whether it fits on the device at all.
② Bytes read per new tokenDecode speed ≈ bandwidth ÷ bytes. Weights dominate at short context, the cache at long context.
③ Math per tokenSets prefill (prompt) speed and batch throughput. Matters on big GPUs and long prompts.
④ QualityWhat the network can still represent and learn. Measured by benchmarks, not computed, so each section cites evidence.

Almost every attention innovation from 2019 to 2026 attacks meter ② (and ① for many users) at long context, while trying to leave ④ untouched. MoE attacks ② and ③ for the weights. Activations and norms mostly move ④ and training stability.

Attention · 1

Multi-head attention (MHA): many readers, each with their own notes

The 2017 baseline. Best quality per head, and the most expensive cache possible.

The problem it solves

One attention pattern per token is not enough. While reading "she gave him the book because it…", one relation links "it" → "book", another tracks grammar, another copies the previous word. A single softmax can only put its weight in one mix.

How it works

  1. Split the hidden vector ( numbers) into heads of .
  2. Each head has its own W_q, W_k, W_v slices, so it learns its own notion of "relevant".
  3. Every head attends separately, the outputs are concatenated, and W_o mixes them back.
  4. For later tokens, every head's K and V for every past token are kept in the KV cache.

Interpretability work finds real specialists among heads: previous-token heads and induction heads, which find an earlier occurrence of the current token and copy what came after it (the basis of in-context copying).[Olsson 2022]

Analogy

32 readers go through the same document, each with a different highlighter and each keeping a full private notebook. Rich, but 32 notebooks fill the shelf.

Worked example on your setup

The price (flaws)

  • Cache = 2 × d × bytes per token per layer. It depends on the width d, not on how many heads you split it into. That's why sharing K/V is the only way to shrink it.
  • Many heads are redundant. Pruning studies removed a large share of heads at test time with little loss,[Michel 2019] which hints the K/V storage is wasteful.

Who uses it

Original Transformer, GPT-2/3, Llama 1, Qwen-7B (2023). New large models have almost all moved away from it.

Try it: more heads gives more, smaller attention patterns. The cache, bytes and math stay identical, because H × head_dim = d.

Attention · 2

Multi-query attention (MQA): everyone shares one notebook

Smallest possible cache among softmax designs. Costs some quality and is awkward on multi-GPU.

The problem it solves

How it works

  1. Keep all query heads, so each still forms its own pattern.
  2. Compute just one K head and one V head per token, shared by every query head.[Shazeer 2019]
  3. The cache shrinks by a factor of .

Analogy

32 readers, one shared notebook. Each reader still asks their own question, but they all look things up in the same notes.

Worked example on your setup

The price (flaws)

  • Quality drops. In the GQA paper's T5-XXL tests, MQA scored a little below MHA on their task average (46.6 vs 47.2), and training was less stable.[Ainslie 2023]
  • Tensor parallelism is wasteful. When 8 GPUs split the heads, each GPU still needs the single K/V head, so it gets copied 8 times.
  • Every query head reads the same K, so heads find it harder to specialize.

Who uses it

PaLM, Falcon-7B, StarCoder, Gemma 1 2B. Mostly replaced by GQA.

Attention · 3

Grouped-query attention (GQA): one notebook per table of readers

The industry default. Nearly MHA quality at a fraction of the cache, and it splits cleanly across 8 GPUs.

The problem it solves

MHA's cache is too big and MQA loses quality. Is there a middle ground?

How it works

  1. Keep query heads. Make g K/V heads, where g divides H.
  2. Each group of H/g query heads shares one K/V pair. In code that's repeat_kv: the stored K/V are broadcast to each head in the group.
  3. Cache ÷ (H/g). With g = 8 and H = 32, it's 4× smaller than MHA.

Why 8 K/V heads so often?

Servers usually split a model across 8 GPUs (tensor parallel). With 8 K/V heads, each GPU owns exactly one and nothing is duplicated. It's a hardware reason, not a magic quality number.

Analogy

32 readers at 8 tables, one shared notebook per table. Readers at a table work on related questions, so sharing costs them little.

Worked example on your setup

Evidence and price

  • T5-XXL averages: MHA 47.2, GQA-8 47.1, MQA 46.6. GQA was nearly as fast as MQA.[Ainslie 2023]
  • An existing MHA model can be uptrained into GQA (mean-pool the K/V heads in each group, then continue training on about 5% of the original compute).
  • The cache still holds full-size K/V vectors, and it still grows linearly with context.

Who uses it

Llama 2 70B and Llama 3, Mistral, Qwen2/2.5/3 (Qwen3-8B: 32Q / 8KV), Gemma 3 (8Q / 4KV), Qwen3.5's full-attention layers.

Attention · 4

Multi-head latent attention (MLA): store a zip file, read it directly

DeepSeek's answer: keep every head distinct but cache one small compressed vector per token.

The problem it solves

GQA saves memory by making heads share, which limits them. MLA asks: can each head keep its own K and V while we store something much smaller?

How it works

  1. Compress: c = W_DKV · x. A latent of numbers per token (DeepSeek uses 512). Only c is cached.
  2. Expand (in principle): each head's k = W_UK,h · c and v = W_UV,h · c, so every head still differs.
  3. Absorb (in practice): since q·(W_UK c) = (W_UKᵀ q)·c, fold W_UK into the query and W_UV into the output. Heads score the cached latent directly, and the full K/V are never built.
  4. The RoPE catch: RoPE rotates k by an angle that depends on position, so W_UK can't be folded through it. MLA adds a small separate 64-dim RoPE key shared by all heads ("decoupled RoPE"). Cache = + 64 numbers.

Analogy

Instead of 32 notebooks, store one zipped page per token. Each reader has a personal decoder. With absorption, the readers learn to read the zip without unzipping.

Worked example on your setup

Evidence and price

  • DeepSeek-V2 reported 93.3% less KV cache than DeepSeek 67B and up to 5.76× generation throughput, and its ablation found MLA matching or beating MHA.[DeepSeek-V2]
  • More math per token in attention: each of 128 heads scores in 512+64 dims. That's fine for decode (memory-bound) but heavier for prefill.
  • It needs special kernels (FlashMLA etc.) and engine support, and converting an existing GQA model takes research-level retraining.

Who uses it

DeepSeek-V2, V3, R1, V3.2; Kimi K2.

Attention · 5

Sliding-window + global layers: most layers only remember the last page

Caps the cache of most layers at a fixed window. Gemma 3 uses 5 local layers (window 1,024) per global layer.

The problem it solves

In a normal model every layer's cache grows with context, yet most attention weight in most layers lands on nearby tokens. Why pay to store 100K tokens in every layer?

How it works

  1. Local layers attend only to the last W tokens. Their cache is a ring buffer of W slots, so it stops growing.
  2. One in every N layers is global and attends to everything.
  3. Distant information reaches a token through the global layers. In a model with no global layers, each layer extends the reach by W.

Analogy

Five of every six team members only remember the last page they read. The sixth keeps the whole book and briefs the others.

Worked example on your setup

Evidence and price

  • The Gemma 3 team reported negligible perplexity change from local:global ratios like 5:1 with small windows, while KV memory dropped sharply.[Gemma 3]
  • Long-range facts must survive through the few global layers, which is a bottleneck for exact retrieval far back.
  • No gain at short context: below W tokens, local and global layers cost the same.

Who uses it

Mistral 7B v0.1 (window 4,096 in all layers), Gemma 2 (1:1), Gemma 3 (5:1, window 1,024), gpt-oss (alternating).

Attention · 6

DeepSeek Sparse Attention (DSA): skim the index, read 2,048 lines

Keeps the whole cache but reads only the top-k tokens each step. Cuts bandwidth and math at long context, not memory.

The problem it solves

Even with MLA's tiny cache, at 128K tokens every new token still reads and attends over all 128K entries in every layer. Per-token attention cost grows linearly with context, and prompt (prefill) cost grows quadratically.

How it works

  1. A lightning indexer (a few small heads, FP8, ReLU) gives every past token a cheap relevance score: I(t,s) = Σ_h w_h · ReLU(q_h · k_s).
  2. Keep the top-k (2,048 in V3.2).
  3. Run full MLA attention only on those tokens.
  4. All tokens stay cached, because any of them might be selected later.

Analogy

Before answering, you skim the book's index (cheap) and then read only the 2,048 most relevant lines carefully.

Worked example on your setup

Evidence and price

  • DeepSeek-V3.2-Exp matched V3.1-Terminus on its benchmarks while long-context inference got much cheaper.[DeepSeek-V3.2]
  • The indexer is still linear in context. It is cheap per token, not free.
  • Selection mistakes are silent: if the indexer skips a needed token, attention never sees it. The indexer has to be trained (continued pretraining).
  • Memory is unchanged. Only meters ② and ③ improve, and only once the context is longer than k.
Attention · 7

Linear attention (Gated DeltaNet): a whiteboard instead of a notebook

A fixed-size memory per layer, so cost does not grow with context. Weak at exact recall, so it's mixed 3:1 with full attention.

The problem it solves

Every design above still has a cache that grows with context somewhere. At 256K–1M tokens that growth dominates both memory and speed.

How it works (per head, per token)

  1. Forget a little: S ← α·S (α ≈ 0.9–1, learned per token).
  2. Predict, then correct: the state predicts v from k as S·k. Only the error is written: S ← S + β (v − S·k) kᵀ. This is the delta rule.
  3. Read: o = S·q.
  4. S has a fixed size (128×128 per head in Qwen3.5) whether the context is 10 or 1,000,000 tokens.

Analogy

A notebook (KV cache) grows a page per token. A whiteboard has fixed space: you smudge old notes a bit (α) and fix entries that are wrong (delta rule). It never runs out of room, but fine details get overwritten.

Worked example on your setup

Evidence and price

  • A d_k × d_v state can cleanly store only about d_k independent key→value pairs. Pure linear models do worse on associative recall (look up an exact earlier fact).[Arora 2023]
  • So production models are hybrids: Qwen3-Next and Qwen3.5 use 3 Gated DeltaNet layers per full-attention layer,[Yang 2024][Qwen3.5] and Kimi Linear also uses 3:1.
  • Prefill can't use the standard FlashAttention kernel, so it needs chunked-scan kernels, and engine support arrives later.
FFN · 8

Mixture of experts: a big library, but each token visits only a few shelves

Store many parameters (knowledge), read few per token (speed). The memory bill still covers all of them.

The problem it solves

Quality grows with parameter count, but in a dense model every parameter is read for every token, so a 70B dense model is slow. MoE separates the parameters you store from the ones you read.

How it works

  1. Replace the FFN with E small FFNs ("experts").
  2. A router scores the experts for each token and keeps the top k (often 8). DeepSeek adds a shared expert that always runs.
  3. Only those k experts' weights are read for this token.

Analogy

A hospital with 128 specialists. Each patient sees the 8 most relevant ones. The building must house all 128 (memory), but each visit costs only 8 consultations (speed).

Worked example on your setup

The price (flaws)

  • Memory follows the total. Qwen3-30B-A3B needs 30B parameters' worth of memory to run at roughly 3B speed.
  • Batching erodes the advantage: with many users in a batch, different tokens pick different experts, so most experts get read every step anyway. Watch the batch slider.
  • Load balancing: without an auxiliary loss or bias, a few experts get all the tokens ("collapse"). DeepSeek-V3 uses bias-based, aux-loss-free balancing.
  • A device win: because each token touches few experts, engines can keep experts in CPU RAM and attention on the GPU (llama.cpp --n-cpu-moe / -ot). That's how 30B-A3B runs well on a laptop.
FFN · 9

ReLU vs GELU vs SwiGLU: why almost everyone picked SwiGLU

SwiGLU gives the best quality at the same parameter count. ReLU gives exact zeros, which CPU engines can exploit.

The problem it solves

Without a nonlinearity, the FFN is just one big matrix, and stacking layers adds nothing. The choice of nonlinearity changes three things: how well the model learns (quality), whether training stays healthy (dead neurons), and how many outputs are exactly zero (skippable at inference).

The three, side by side

  • ReLU max(0,z): cheap, and gives exact zeros. But any neuron pushed below zero for every input has gradient 0 forever (a dead neuron).
  • GELU z·Φ(z): a smooth ReLU. Small negatives pass through slightly, so the gradient never dies. Used by GPT-2 and BERT.
  • SwiGLU SiLU(x·W_g) ⊙ (x·W_u): two projections, one acting as a learned gate for the other. The network can multiply features, not just threshold them.

The parameter trick you must know

SwiGLU has 3 matrices instead of 2. To keep the parameter count equal, the hidden width shrinks from 4d to 8/3·d. That's why Llama-7B's FFN is 11,008 wide (≈ 2.69 × 4,096), not 16,384. Compare them at equal parameters or the comparison is unfair.

Evidence

Same parameter count, same training (T5, 65K steps), log-perplexity on C4 (lower is better):[Shazeer 2020]

Analogy

ReLU is a light switch: off below a threshold, and it can get stuck off. GELU is a dimmer. SwiGLU is a dimmer controlled by a second sensor: one signal decides how much of the other gets through.

The practical twist: sparsity

ReLU's exact zeros mean those rows of W_down need not be read at all. CPU and phone engines (PowerInfer) exploit this, and "ReLU strikes back" showed models can be converted back to ReLU, cutting inference FLOPs severalfold with small quality loss.[Mirzadeh 2023] SwiGLU almost never outputs an exact zero, so it can't skip work this way.

Small choices, big effects · 10

Pre-norm, RMSNorm, QK-Norm and the RoPE base

These rarely change speed. They decide whether a 60-layer model trains at all, and how far its context can stretch.

Pre-norm instead of post-norm

Problem: the original Transformer normalized after the residual add. Deep stacks then need careful learning-rate warmup and often diverge.
Change: normalize the input to each block, and leave the residual path as pure addition. The gradient flows straight down the stream.[Xiong 2020]
Effect: 60+ layers train reliably. Price: the stream's size keeps growing with depth, which is why a final norm sits before the LM head.

RMSNorm instead of LayerNorm

Change: drop the mean subtraction and bias, and only divide by the root mean square. Effect: the same quality with fewer operations. The authors measured 7–64% less norm runtime in their models.[Zhang 2019] Price: essentially none, which is why every model here uses it.

QK-Norm

Problem: during training, q·k logits can drift huge, making the softmax one-hot and the loss spike ("attention logit growth").[Dehghani 2023]
Change: RMS-normalize every q and k head before the dot product. Effect: scores stay bounded and training is stable. Qwen3 adopted it and dropped the QKV bias, and Gemma 3 used it to replace logit soft-capping. Price: a tiny amount of compute.

RoPE base θ: how far positions can reach

RoPE rotates each pair of dimensions at a different speed. The slowest pair completes one turn every 2π·θ(d−2)/d tokens. Past that distance, positions start to look alike. A bigger θ gives slower rotations and a longer usable context. Qwen3 uses θ = 1,000,000. YaRN rescales the frequencies to stretch a trained 32K model to 128K.

Editing a trained model · 11

Abliteration: removing the "refuse" direction

Refusal in chat models is largely controlled by one direction in the residual stream. Remove it from every weight that writes to the stream, and the model loses its ability to refuse.

Why it works

Remember the residual stream (Part 3): every layer adds its output into one shared vector. Researchers found that when a chat model is about to refuse, the stream points noticeably along one particular direction r. If you push along r, harmless prompts get refused; if you remove r, harmful prompts get answered.[Arditi 2024]

The procedure, step by step

  1. Two prompt sets: about a hundred instructions the model refuses, and a hundred similar ones it answers.
  2. Record: run both sets and save the residual-stream vector at the last prompt token, at a middle layer ℓ.
  3. Find the direction: r = mean(refused) − mean(answered), then normalize it to r̂ = r / ‖r‖. This is a difference of means, nothing more.
  4. Choose the layer: repeat for several layers and keep the r̂ whose removal works best on held-out prompts.
  5. Remove it permanently: for every matrix that writes into the stream (token embedding, each attention W_O, each FFN W_down), set W ← W − r̂ r̂ᵀ W. Now no layer can write anything along r̂.
  6. Check: refusal rate on held-out prompts, general benchmarks, and the KL divergence from the original model on harmless prompts.
# the whole edit is one projection per matrix (r_hat: unit vector, shape [d_model])
P = torch.eye(d_model) - torch.outer(r_hat, r_hat)   # removes the r_hat component
W_O    = P @ W_O        # attention output, every layer
W_down = P @ W_down     # FFN output, every layer
E      = E @ P          # embedding rows (tokens × d_model)

Analogy

A mixing desk where one hidden fader, "refuse", is wired into every channel. Abliteration doesn't turn it down; it removes that wire from every input, so nothing can ever move the fader.

Effects and flaws

  • It removes a behavior, not knowledge. The model knows nothing new, it just loses its brake.
  • Collateral damage: other behaviors that partly align with r̂ weaken too. Abliterated models often lose a little on math or reasoning, and people "heal" them with a short fine-tune.
  • It's a rank-1 edit: the weights stay the same size and speed, so quantize after editing, as usual.
  • Responsibility: it strips the safety behavior the developers trained in. Use it for interpretability and robustness research, and know the model license and your organization's policy.

This is a real computation on a toy 3D stream: 60 "answered" points and 60 "refused" points. The page computes r̂ as the difference of means, then projects. Real models do the same in 4,096 dimensions.
